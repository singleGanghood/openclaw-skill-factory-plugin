# 数据隔离设计模式（Data Isolation Patterns）

> 数据边界封闭的完整设计规范：数据流、脱敏规则、字段白名单、哈希化、进程内自取凭证、加密落盘。

---

## 一、核心数据流（数据边界图）

```
┌─────────────────────────────────────────────────────────────┐
│  脚本进程（数据边界，LLM 完全不可见）                          │
│                                                             │
│  ① 取 ID：  实例元数据服务 / 本地身份文件（进程内自取）         │
│  ② 取凭证： 内部鉴权接口链式签发临时 token（用 ① 的 ID 换）     │
│  ③ 调接口： 敏感接口 + ID 鉴权/路由（强制 HTTPS）              │
│  ④ 拿数据：  raw = resp.json()   ← 只存内存变量               │
│  ⑤ 处理：    白名单 + 脱敏 + 哈希                              │
│  ⑥ stdout：  只 print 脱敏结论（不含 ID/凭证/raw）             │
└─────────────────────────────────────────────────────────────┘
        ▲                                    │
   进程内自取(ID/凭证)                  脱敏结论(唯一出口)
        │                                    ▼
   [不在上下文]                        [进入 session，已脱敏]
```

> **零外部环境变量**：ID 与凭证都在进程内自行获取，全程无需 env 注入。
> env 仅作为**可选调试覆盖**（`<PREFIX>_TOKEN` / `<PREFIX>_INSTANCE_ID`），默认不依赖。

**关键结论**：私有数据进入 session / thinking 的唯一入口，是脚本的 stdout 返回值。
只要数据不通过 stdout 吐出来，模型就"看不到"它，自然无从泄露。

---

## 二、零泄露的前提：数据不进上下文

| 数据来源 | 是否进上下文 | 是否安全 |
|----------|-------------|---------|
| 实例元数据服务（云上 `169.254.169.254`） | ❌ 不进 | ✅ 最佳（进程内自取） |
| 内部鉴权接口链式签发临时 token | ❌ 不进 | ✅ 最佳（动态凭证，用后即弃） |
| 本地身份文件（`/etc/machine-id` 等机器自身身份） | ❌ 不进 | ✅ 进程内读取 |
| 环境变量（可选调试覆盖） | ❌ 不进 | ✅ 可选，默认不依赖 |
| SKILL.md 硬编码 | ✅ 进 | ❌ 绝对禁止 |
| 命令行参数由 Agent 传入 | ✅ 进 | ❌ 命令串进 session |
| 模型从别处查到再传 | ✅ 进 | ⚠️ 已泄露，只能降级 |

## 三、脱敏规则

### 字段白名单（默认最小集）

只放行非敏感字段，新增字段需先改白名单再决定放行：

```python
ALLOWED_FIELDS = {"doc_id", "title", "summary"}
```

### 敏感字段打码（mask）

```python
SENSITIVE_KEYS = {"owner", "uin", "phone", "email", "secret"}

def mask(v):
    if not isinstance(v, str) or len(v) <= 2:
        return v
    return v[0] + "*" * (len(v) - 2) + v[-1]
```

### 可识别标识哈希化

`doc_id` / `uin` 等唯一标识，用哈希替代，保留"可比对性"但不可还原：

```python
digest = hashlib.sha256(ids_json.encode()).hexdigest()[:16]
```

## 四、凭证与实例 ID：进程内自取（零环境变量）

核心原则：**全程无需外部环境变量**。ID 与凭证都在脚本进程内自行获取：

| 环节 | 获取方式 | 是否依赖 env |
|------|----------|-------------|
| 实例ID | 云元数据服务（`169.254.169.254/latest/meta-data/instance-id`）或本地身份文件（`/etc/machine-id` / `/var/lib/cloud/data/instance-id`） | ❌ 否 |
| 临时凭证 | **链式签发**：用实例ID调内部鉴权接口（`AUTH_API`），换取临时 token | ❌ 否 |
| 接口地址 | 内网地址默认内置（非机密），可 env 覆盖 | ❌ 否（内置默认） |

链式调用链路：

```python
iid   = acquire_instance_id()       # ① 自取实例ID（元数据服务/本地身份）
token = acquire_credential(iid)     # ② 用 ID 换临时 token（内部鉴权接口）
raw   = fetch_data(token, iid, q)   # ③ 用 token 调敏感接口取数据
```

原则：
- skill 文件（SKILL.md + scripts/）可提交版本库，**不含任何机密**（凭证是运行时动态签发的临时 token，实例ID 是机器自身身份）
- ID / token / 原始数据只在脚本进程内存中存活，不进 LLM 上下文、不落盘
- 环境变量仅作为**可选调试覆盖**，默认完全不依赖

> **安全边界**："不用 env" ≠ "把凭证硬编码进 skill 文件"。硬编码才是真泄露
> （skill 文件会进上下文/版本库）。正确做法是让凭证来自"实例自身身份 + 动态签发"。

## 五、传输加密与存储加密

| 层 | 手段 | 说明 |
|----|------|------|
| 传输层 | 强制 HTTPS | 接口地址必须 `https://`，禁止明文 HTTP |
| 存储层（默认） | **不落盘** | 原始数据只用内存变量，进程结束即销毁 |
| 存储层（进阶） | AES-GCM 加密落盘 | 仅在必须缓存时启用，密钥进程内生成/自取，用后删除临时文件 |

> 本能力包默认走"内存处理 + 不落盘"，保持零第三方依赖。落盘加密作为进阶手段，
> 需引入 `cryptography` 依赖，仅在确有必要时启用。

---

## 六、禁止事项（红线）

- ❌ 禁止 `print(raw)` 或任何形式输出原始响应
- ❌ 禁止把 Token / 实例 ID 写进 SKILL.md、description、命令行参数
- ❌ 禁止把原始数据写到日志文件、临时文件（除非加密且用后删除）
- ❌ 禁止在 description 中写真实数据（接口地址、字段名、实例 ID）
- ❌ 禁止模型复述、引用脚本返回结论之外的任何原始字段

---

## 七、可接受泄露面（豁免）

- description 中声明"本 skill 涉及数据隔离"（`DATA-GUARD`）—— 只暴露"存在该能力"，不暴露数据本身
- 脚本返回的 `hit_count` / 脱敏标题 / 哈希 digest —— 已脱敏，不可还原
