# Skill 评估评分标准（Scoring Rubric）

> 总分 100 分，7 个维度，基于 Anthropic Agent Skills Specification V1.0

---

## 维度 1：目录结构规范（10分）

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 文件夹命名 | 3分 | kebab-case，与 `name` 字段一致 | 不一致 -3；有大写/下划线/空格 -3 |
| SKILL.md 存在且命名正确 | 3分 | 文件名完全一致 `SKILL.md` | 不存在 -3；大小写错误 -3 |
| 资源文件归位 | 2分 | 脚本在 scripts/、参考在 references/、资源在 assets/ | 每有一个放错位置 -1 |
| 无违规文件 | 2分 | 根目录无 README.md、无散落的非 SKILL.md 文件 | 有 README.md -1；有散落文件 -1 |

### 评分指南

- **10分**：完美结构，无任何违规
- **7-9分**：结构基本正确，有轻微瑕疵（如有空的子目录）
- **4-6分**：存在明显问题（文件放错位置）
- **0-3分**：结构严重违规（无 SKILL.md 或命名完全不合规）

---

## 维度 2：Frontmatter 质量（15分）

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| YAML 格式正确 | 3分 | 用 `---` 正确包裹，可被解析 | 格式错误 -3 |
| `name` 合规 | 4分 | kebab-case, [a-z0-9-]+, ≤64字符, 无 `--`, 不以 `-` 开头/结尾 | 每违反一条 -2 |
| `description` 存在且非空 | 3分 | 1-1024字符 | 缺失 -3；超长 -1；太短(<30字符) -2 |
| 无安全违规 | 3分 | 无 `<>`，不含 `claude`/`anthropic` | 每违反一项 -1.5 |
| 可选字段 bonus | 2分 | 有 license/metadata/compatibility 等 | 有任意一个可选字段 +1，最多 +2 |

### 评分指南

- **13-15分**：frontmatter 完美，含可选字段
- **10-12分**：必填字段正确，无可选字段
- **6-9分**：有轻微问题（name 与文件夹名不一致等）
- **0-5分**：严重问题（YAML 无法解析、缺必填字段）

---

## 维度 3：Description 触发效能（20分）—— 权重最高

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 含指令式骨架 | 5分 | 有 `ALWAYS invoke` 或等效强制指令 | 无强制指令 -5；用 `Use when` -2 |
| 触发关键词覆盖 | 5分 | 列出 5+ 个口语化触发词/短语 | 无触发词 -5；<3个 -2；太书面 -1 |
| 排除边界 | 4分 | 有 `Do NOT use for` + 具体场景 | 无排除 -4；排除太模糊 -2 |
| 长度适中 | 3分 | 3-5行（100-400字符） | 超8行 -2；只有1行 -2 |
| 多语言覆盖 | 3分 | 中英文触发词兼有（如面向双语用户） | 仅单语言且面向双语用户 -2 |

### 评分指南

- **18-20分**：指令式、触发词丰富、边界清晰、长度适中、多语覆盖
- **13-17分**：基本要素齐全，但某方面可优化
- **8-12分**：缺少关键要素（如无排除边界或无触发词）
- **0-7分**：description 基本无效（太模糊/太短/格式错误）

### 触发效能快速诊断

```
✅ 高效 description 特征：
- ALWAYS invoke / MUST trigger
- Trigger keywords: '...', '...', '...'
- Do not ... directly — use this skill first
- Do NOT use for ...

❌ 低效 description 特征：
- "Helps with ..."（太模糊）
- "Use when ..."（太被动）
- 无关键词列举
- 无排除条件
```

## 维度 4：正文结构完整性（15分）

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| Quick Reference | 2分 | 有资源索引表格 | 缺失 -2；有但引用断裂 -1 |
| Overview / 概述 | 2分 | 清晰说明功能和支持模式 | 缺失 -2；太模糊 -1 |
| When to Use | 3分 | ✅ 适用 + ❌ 不适用 都有 | 缺失 -3；只有适用没有不适用 -1 |
| Workflow | 4分 | 有清晰的分步流程 | 缺失 -4；步骤不清晰 -2 |
| Examples | 2分 | 至少 1 个完整示例 | 缺失 -2 |
| Troubleshooting | 2分 | 至少 1 个常见问题 | 缺失 -2 |

### 评分指南

- **14-15分**：全部章节齐全且组织清晰
- **10-13分**：核心章节齐全，缺少 1-2 个辅助章节
- **6-9分**：缺少多个重要章节
- **0-5分**：结构混乱或严重缺失

---

## 维度 5：内容质量与可执行性（20分）—— 权重并列最高

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 指令具体可执行 | 6分 | 每个步骤有明确操作（命令/代码/路径） | 模糊指令每处 -1，最多 -6 |
| 示例完整性 | 4分 | 示例含：用户输入 → 执行过程 → 预期输出 | 示例不完整 -2；无示例 -4 |
| 错误处理覆盖 | 3分 | 常见失败场景有对应方案 | 无错误处理 -3；覆盖不足 -1 |
| 资源引用正确性 | 3分 | 引用的文件确实存在且路径正确 | 断裂引用每处 -1 |
| 内容一致性 | 2分 | 正文描述与 description 功能一致 | 不一致 -2 |
| 无冗余 / 精炼 | 2分 | 无重复内容、无无关信息 | 明显冗余 -1 |

### 评分指南

- **18-20分**：每个指令都可立即执行，示例完整，错误处理全面
- **13-17分**：大部分指令可执行，有少量模糊处
- **8-12分**：存在较多模糊指令或缺少示例
- **0-7分**：内容大部分不可执行或严重缺失

---

## 维度 6：Token 效率与渐进加载（10分）

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 正文长度控制 | 4分 | ≤5000字 / ≤500行 | 超5000字 -2；超8000字 -4 |
| 分层合理性 | 3分 | 核心在正文，详细在 references/ | 全部内容堆在正文 -2；该放正文的放到 references -1 |
| Quick Reference 索引 | 3分 | 用表格清晰索引 references/assets | 无索引 -3；索引不完整 -1 |

### 评分指南

- **9-10分**：分层清晰、长度适中、索引完整
- **6-8分**：基本合理，轻微偏差
- **3-5分**：明显问题（正文过长或无分层）
- **0-2分**：严重违反（全部堆积无分层）

---

## 维度 7：生态兼容性（10分）

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 边界不与其他 Skill 冲突 | 4分 | description 排除条件与相似 Skill 互补 | 与已知 Skill 描述重叠 -2 到 -4 |
| 可组合性 | 3分 | 可被其他 Skill 引用或串联 | 设计为孤岛不可组合 -2 |
| 依赖声明 | 3分 | 明确列出依赖（工具/环境/其他 Skill） | 有隐式依赖未声明 -1.5 |

### 评分指南

- **9-10分**：边界清晰、可组合、依赖透明
- **6-8分**：基本兼容，轻微边界模糊
- **3-5分**：存在冲突风险或未声明依赖
- **0-2分**：严重冲突或完全不可组合

---

## 维度 8：数据隔离与安全（安全门禁，10分制）

> **仅涉敏 skill（`securityMode != none`）评估**。非涉敏 skill 记 `N/A`，不影响总分。
> 评分 < 6 分即**一票否决**：整体判定「不达标」，必须回喂 `skill-data-guard` 加固。

| 评分项 | 分值 | 满分条件 | 扣分规则 |
|--------|------|----------|----------|
| 接口脚本化封装 | 3分 | 接口调用封闭在 scripts/ 脚本内，模型不直接发请求 | 无脚本封装 -3 |
| stdout 脱敏输出 | 3分 | stdout 只输出白名单字段/脱敏结论，无原始数据 print | 有原始数据 print -3 |
| 凭证进程内自取 | 2分 | Token/实例ID 进程内自取（链式签发/元数据服务），无硬编码 | 硬编码 -2 |
| 数据边界铁律 | 2分 | SKILL.md 含 Data Boundary 章节 + description 含 DATA-GUARD 声明 | 缺失 -2 |

### 评分指南

- **8-10分**：数据边界封闭完整，四要素齐备
- **6-7分**：基本达标，个别项可加固（如缺 DATA-GUARD 声明）
- **0-5分**：存在泄露风险，一票否决，必须回喂加固

## 总分等级对照

| 总分 | 等级 | 建议 |
|------|------|------|
| 90-100 | ⭐ 卓越 | 可直接发布/共享 |
| 80-89 | ✅ 优秀 | 少量优化即可发布 |
| 70-79 | 🟡 良好 | 需要针对性改进 |
| 60-69 | 🟠 及格 | 需较大幅度优化 |
| 40-59 | 🔴 不及格 | 建议重构核心部分 |
| 0-39 | ❌ 严重不达标 | 建议使用 skill-generator 重新生成 |
